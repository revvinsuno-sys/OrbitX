# OrbitX

OrbitX is a Windows game library and PS5 emulator frontend.

Starting an installation moves the existing download card into Installations. Failures stay there with local Retry installation and Delete actions. Successful installations move to My Library. Downloads continues to show an installed source only when it was retained; files that still exist cannot be hidden with Clear history. Source cleanup failures remain visible in Installations for explicit retry.

Downloads retain the selected catalogue entry/source IDs and its cover and fallback artwork URLs. My Library receives the same metadata when a download completes, so artwork remains available after restart or when a source is disabled. Older download records gain artwork on catalogue refresh only through an exact source/entry ID match; filenames and titles are never used to infer a match. Artwork images remain in the existing bounded in-memory thumbnail cache.

A Windows WPF catalogue browser, download manager and KytyPS5 frontend. It does not modify KytyPS5 or connect to a console.

## Build and run

Requires Windows, Node.js 22 and the .NET 10 SDK/runtime with Windows Desktop support. Orbit and embedded downloads require the Microsoft Edge WebView2 Evergreen Runtime. The app references the pinned `Microsoft.Web.WebView2` NuGet package; the repository's NuGet configuration uses nuget.org. The build restores the locked React/Vite frontend dependencies when missing.

```powershell
dotnet build .\PS5CatalogBrowser.slnx -c Release
dotnet run --project .\PS5CatalogBrowser.App\PS5CatalogBrowser.App.csproj -c Release
dotnet run --project .\PS5CatalogBrowser.Tests\PS5CatalogBrowser.Tests.csproj -c Release
dotnet run --project .\PS5CatalogBrowser.BrowserTests\PS5CatalogBrowser.BrowserTests.csproj -c Release
```

The core test project is a dependency-free automated console runner. BrowserTests runs actual WebView2 downloads against small loopback HTTP fixtures, with a temporary browser profile and download folder. It tests landing pages, redirect downloads, unknown lengths, interruption, confirmation rejection, pause/resume, cancellation, restart reconciliation and external-file import. A nonzero exit code indicates failure. For a manual local page and confirmation-dialog smoke test, add `-- --interactive` to the BrowserTests command. Only the test harness clicks its own local fixture links; the application never clicks third-party download buttons.

Launch the Release executable from Windows Explorer for normal use and restart validation.
Windows can redirect AppData writes from a packaged development host into its private
LocalCache, creating a different settings view from a normal desktop launch. Preserve
both settings snapshots before reconciling such a split; do not overwrite the user's
desktop settings with a development-host snapshot.

## Using the app

**Interface → Orbit Store** opens the genuine Orbit 1.3.5 frontend with Store, Crossbar, Cinema and Panorama layouts. Use **arrow keys or WASD**, **Enter** and **Escape**; typing keeps its normal behaviour. **Appearance (F2)** opens the layout chooser from any screen. To download: open a game, choose **View releases** where shown, select the source/version, press **Download**, then choose **Download**, **Browser-assisted download**, or external browser/import according to that provider. **Downloads** shows the real Windows queue with pause/resume, cancellation, history, extraction and installation controls. **My Library** manages the existing installed entries, reinspection, launch and confirmed file deletion. Settings uses horizontal category tabs for catalogue sources, downloads, archive passwords, the embedded browser, image installation, Emulators and About OrbitX. The Emulators page exposes each emulator's **Start full screen** setting; clearing it starts games windowed. KytyPS5 arguments are inside the Emulators page. Orbit opens those same bound controls in an in-app settings view; fullscreen hides the Windows Settings toolbar button and keeps Settings in the fullscreen window. Back or Escape returns to Orbit, preserving the selected tab and draft argument edits. F11 changes fullscreen state without closing Settings. About OrbitX displays the assembly build version and local build time. Classic Windows remains the initial default and is available from the native toolbar. Both interfaces share the same C# owners, records and confirmations. F11 toggles Orbit-only fullscreen. The native toolbar slides away; move the pointer to the top edge or press F6 to reveal it. **Close** at the far right of the menu uses normal application shutdown and its active-download safeguards. The native status strip and padding stay hidden until fullscreen exits. The wheel scrolls horizontal Orbit panels sideways, while nested vertical panels keep normal scrolling. Save to is a read-only display of the configured download path at the end of the game details choices. See [frontend contracts and provenance](orbit-frontend.md) and [validation results](orbit-frontend-validation.md).

- **Browse:** both default sources refresh on startup. Search by title, description or title ID; filter by source, kind or platform; sort by title, source, version or size. Select an entry to see metadata, artwork and individual mirror rows with provider, release group, filename, format, size and host. Mirrors with a known matching filename and release group are alternatives; choose one source per file. **Direct download** uses HTTP for direct-file URLs. **Browser-assisted** opens the selected website in an embedded window for you to complete its normal workflow. **Download all files** is available for PS5 Library multiple-file entries; OptiStore links must be chosen individually.
- **Downloads:** direct and browser transfers share the page. Files stay in an app-owned `.ps5catalog-staging` job directory under their reserved root until transfer completion and size/checksum verification succeeds. A durable completion intent is saved before promotion; startup re-hashes interrupted completions and safely finishes local promotion/library registration. Conflicting, missing or changed files show **Needs attention** and remain preserved. Publishing never overwrites an existing file. Cancellation stops before durable finalisation; unresolved completion evidence cannot be discarded or cleared. Native browser pause/resume is available in the current session. Eligible direct HTTP downloads support Pause/Resume across application restart using a strong ETag and a durable owned checkpoint. Resume validates the partial and a conditional 206 response before appending; unsupported or changed representations retain their bytes for explicit Restart/Discard. Restart confirms data loss and reuses the original job from byte zero; browser transfers interrupted before verification must be opened again manually from Browse. See [the completion contract](download-completion.md) and [HTTP resume contract](http-download-resume.md).
- **My Library:** shows registered content inside the configured Installed directory. Completed ELF downloads and extracted game folders move there after full-content hashing and ownership checks. Installation no longer depends on the browser's Kyty ELF/SELF checker; Kyty determines compatibility when launched, and failed launches preserve the game. **Extract and install** handles ZIP/RAR in Downloads and retains the source archive. **Install** accepts PS4/PS5 debug or fake PKGs and exFAT images. Existing no-overwrite moves, verification manifests, deletion confirmation and recovery remain in place. See [PKG and RAR installation](package-and-archive-installation.md) and [content movement](runnable-content-movement.md).
- **Settings:** add, edit, disable, remove and test JSON sources. Choose a Downloads directory and `kyty_emulator.exe`. Select the installed games directory separately under Image Installation; it is never derived from Downloads. Both directory fields save edits immediately, and changing either does not move existing files. An unset installed games directory must be selected before installation. Settings and records are saved atomically in `%LOCALAPPDATA%\PS5CatalogBrowser\settings.json`; downloads default to `%USERPROFILE%\Downloads\PS5Catalog`.

Browse uses square cover tiles with titles underneath and a library caption for matching saved records. Select a tile to open details; **Close details** restores the full grid. A missing or failed primary uses the catalogue's explicit cover fallback; if neither works, a placeholder remains. Artwork is fetched near the visible rows, with four concurrent requests, a 4 MiB response limit, bounded decoded dimensions and a 128-image memory cache. Download and extracted sizes are shown in decimal GB (1 GB = 1,000,000,000 bytes), including release-option ranges and download progress. Exact byte counts remain unchanged for integrity/admission. Sizes below 0.01 GB retain an explicit small-size label.

Each successfully parsed source is also saved as its original JSON under `%LOCALAPPDATA%\PS5CatalogBrowser\catalogues`. If a refresh fails, Browse loads the last saved copy for that source ID and URL, and Settings shows the refresh error. Editing a source URL starts a separate cache; it will not reuse data from the old address. A source with no saved copy remains unavailable until a successful refresh.

Downloads shows one contextual primary action and a format-specific explanation. Transfer and history controls are grouped under **More actions**. PS4/PS5 debug or fake PKGs can be installed and ZIP/RAR archives extracted. Unsupported image formats, encrypted retail PKGs and 7z are explained beside the selection.

Adding a managed download keeps the current Orbit screen and shows a five-second **Download added** toast. Accepting a provider download minimises its embedded browser window and returns focus to the main app; the window remains alive to finish the transfer. The bandwidth setting is available in Settings in both interfaces.

On failed download rows, **Retry** first resumes a trusted HTTP partial or its live native browser operation when possible. If resume fails, it replaces only that job's owned partial and tries a direct download again from zero. Invalid HTTP links and browser sessions that need fresh verification open the item's Orbit store page so you can choose another download. Completed archives/packages with extraction or installation failures are preserved while returning to the store. Choosing a replacement retires failed rows for that retried item when the new download is admitted; active downloads and other successful versions stay intact. Failed installation rows linked to an exact recorded download offer the same Retry action. Missing catalogue items return to Browse with a refresh message.

On Downloads, **Cancel download** stops an active or queued transfer and keeps incomplete browser/import data. **Clear selected history** and **Clear completed history** clear only completed records with no remaining source files; active, incomplete and retained sources stay visible. **Discard incomplete** asks for confirmation, cancels the selected writer, waits for confirmed termination, and deletes only its verified staging files. Choose No, or leave the record untouched, to keep incomplete data. Failed cleanup stays visible and can be retried. **Delete** on a failed download uses the same confirmed, owned-partial cleanup. Opening Downloads for the first time runs a background inventory refresh; **Scan downloads** refreshes it again. Both inventory every top-level file and extracted folder in place and restores cleared records whose sources still exist. It does not start installations. The refresh reads names and sizes, without hashing sources or opening archives. Hash-dependent, ambiguous or missing metadata stays visibly labelled; full verification happens during installation. Private transfer/extraction staging, Installed and filesystem links are skipped; extracted folders appear as one card each. Unknown files stay visible without gaining install support. Repeated scans do not duplicate files or records. ZIP/RAR extraction tries the selected release's supplied password, then the ordered list in **Settings → Archive passwords**, defaulting to Orbit's six published source passwords. Edit, add or remove one password per line; case and spaces are preserved. Retries reuse the existing archive and stop on success. Exhausted password attempts show a **Password protected** badge and return control without a warning dialog. Archives remain available for another retry after editing the list. **Open downloads folder** opens the configured download root in File Explorer.

The embedded browser uses a dedicated `%LOCALAPPDATA%\PS5CatalogBrowser\browser-profile`. Native offers whose filenames exactly match the selected expected filename are accepted automatically. Missing or different expected filenames still ask for confirmation; all size, checksum and native ownership checks remain in place. Cookies and resolved signed download URLs are not written to application download records or logs, and native transfers remain in WebView2 rather than being replayed through HTTP. Keep the browser window open while transferring; closing it interrupts its active WebView2 transfers. Before a file is accepted, closing only leaves the provider webpage and no download record exists. Cancellation and closure retain download records, but WebView2 may remove partial bytes; **Discard incomplete** removes any remaining owned staging data. The app blocks local-file navigation, custom URI schemes, certificate overrides and site permission requests. Popup windows are blocked automatically by default, with a counter and the provider page kept open. If a site needs a legitimate popup, turn off **Block popup windows** to review user-requested popups individually; unsolicited popups remain blocked. Close browser windows and use **Settings → Clear browser site data** to remove saved site sessions.

Orbit's release dialog shows instructions beside each available method: direct download, provider browser, external browser, completed-file import and listed-file batches. The embedded provider window keeps its provider-specific guidance visible. For AkiraBox `.com` and `.to` file pages, complete any verification yourself and wait without clicking the site's Download button. When its visible ready link matches the selected filename, this app follows it in the same WebView and automatically accepts a matching file offer. **Reload** returns to the original file page for a fresh link. A provider error or absence of a ready link does not create a transfer.

If a provider does not work in WebView2, use **Open in external browser**, complete the transfer there, then **Import completed external download**. This explicitly copies the selected file into staging, verifies available metadata and adds it to My Library as **Imported**. Abandon or cancel external workflows in that browser; the app cannot stop those transfers. External browser progress cannot be captured, and without a catalogue checksum transfer completeness remains unverified. Browser temporary files such as `.crdownload` are rejected. Downloaded files and scripts are never automatically executed.

Default sources are [PS5 Homebrew Catalog](https://homebrew.page/catalog/v1.json) and [evoX-CoreOS Payloads](https://nexgen999.github.io/evoX-CoreOS/json/payloads.json). Catalogue formats are detected by an `apps`, `entries` or `payloads` array, or by OptiStore's `packages` array/map, `DATA` map or bare array. Add [OptiStore's PS5 catalogue](https://raw.githubusercontent.com/OptiTronOffical/OptiStore/main/ps5-catalog.json) in Settings if desired. The OptiStore adapter also accepts its `dlps.json`, `pippo.json` and `pfs.json` shapes, including `downloadLinks` and `files`. Its alternatives, update/DLC links and numbered parts remain separate in details; link labels, groups, versions, regions, hosts and filenames are retained where supplied. The PS5 Library adapter accepts `files` and `source_sets`; matching positions in alternative sets appear as mirrors of the same file. Source identities remain separate even if title IDs overlap. An offline source reports its own error and does not clear entries from healthy sources.

For local testing, see [examples/local-catalog.json](../examples/local-catalog.json). Serve it and an authorised fixture over loopback HTTP, then add `http://127.0.0.1:8000/local-catalog.json` in Settings. Remote catalogues and downloads require HTTPS. Redirect destinations are checked against the same policy.

The read-only preview updates while editing; an unsaved message distinguishes draft options from saved launch settings. New configurations suggest 1280 × 720, Vblank 30, Fifo, Performance and overlay enabled. Existing settings without argument configuration continue to use their previous emulator defaults until the structured controls are explicitly enabled and applied. There was no prior persisted manual argument field in this checkout. Additional Arguments are retained verbatim; with structured controls disabled, managed flags may be entered there once each. Paths containing spaces use double quotes. Vblank 30 does not guarantee a 30 FPS cap.

Classic My Library and Orbit cover/Play actions share `MainViewModel.Launch` → `KytyLauncher`. With KytyPS5 selected, it supplies exactly one `--game` and the application-selected path, then the same options used by the preview through `ProcessStartInfo.ArgumentList`, with the emulator directory as the working directory and no shell. Its Vulkan pipeline cache is populated during gameplay and reused on subsequent runs, subject to title metadata and GPU/driver compatibility. CPU patches and Red Zone protection are optional compatibility settings, not universal boot-crash fixes. No performance improvement or gameplay acceptance is claimed by these controls.

## Recognised files and KytyPS5

- ZIP/RAR: bounded, staged extraction. Traversal, absolute paths, symlinks, unsafe names, duplicate destinations and excessive expansion are rejected. A ZIP is not treated as launchable until an extracted game root contains `eboot.bin`.
- Game directory: launch attempt available when `eboot.bin` is at the selected game root. The nested scanner can locate that root after extraction.
- ELF: direct launch attempt when the file has an ELF header. Console payloads are labelled and prompt a warning.
- ZArchive (`.zar`): retained, but direct launch is disabled until support for the selected KytyPS5 build is confirmed and its contents can be inspected.
- `.exfat`: explicit installation with OSFMount, complete extraction and full verification, described below.
- `.pkg`: explicit PS4/PS5 debug or fake package installation. `.ffpkg`, `.ffpfs`, `.ffpfsc` still require conversion or external extraction. Other formats are retained and marked unsupported.

In Settings, select an existing `kyty_emulator.exe`. The launcher uses `ProcessStartInfo.ArgumentList` with `--game` and the local path, and sets the working directory to the emulator directory. Starting the process records only a launch attempt; it does not prove gameplay. This version does not install packages, convert images, decrypt data, or run catalogue instructions.

When the launched KytyPS5 process exits, the browser restores its window and returns to **My Library** in the selected interface, preserving the launched library entry and its saved log. Nonzero exits show the exit code and a reminder to view the log. The browser must remain open to receive this return. The locally customised KytyPS5 build provides an **Xbox / PS button** or **F10** game menu: use the D-pad or left stick to choose **Continue** or **Exit to library**, **A / Cross / Enter** to select, or **B / Circle / Escape** to continue. The menu captures game controls but does not suspend guest execution; it explicitly states that the game continues running. Guide-button availability depends on the controller and Windows input driver; F10 remains available.

Build identification retains Git's commit-distance/hash and `-dirty` suffixes, so a customised or newer main-branch build is distinguishable from its last tag in the library and compatibility records.

## exFAT image installation

Install [official PassMark OSFMount](https://www.osforensics.com/tools/mount-disk-images.html) **3.3.1000 or later**, including its driver, under Program Files on 64-bit Windows 10/11. Restart Windows if its installer requests it. In **Settings → Image Installation**, detect or select `OSFMount.com` and test availability. The console executable and its `OSFMount.exe` companion must have valid PassMark Authenticode signatures and meet the version requirement. A loose executable in a user tools/download folder is rejected. Availability checks validate executable prerequisites; the installed driver's ability to load and UAC approval are checked during mounting. The app never installs the driver. Only the small mount helper runs elevated for the current session; the browser remains at its normal privilege level. The authenticated pipe requires elevation under the same Windows account. There is no persistent administrator setting.

The default destination is `<configured library/download root>\Installed`; an explicit installed-games setting overrides it. The retain-original preference defaults to off. Choose a completed `.exfat` download, a library image, or **My Library → Install from file**. Install is unavailable for missing, implausible, incomplete or owned images and while another installation is active. First approve read-only inspection, then confirm the mounted image's game title, proposed destination, image/content sizes, free space and **Delete original image after successful installation** checkbox. Confirming a download never starts installation.

Names come from the game root's `sce_sys/param.json` localized title, then the matching catalogue/library title, then the image filename without its extension. Known PS5 `PPSA` title IDs are retained. Invalid Windows characters, device names, trailing spaces/dots and traversal sequences are sanitised into one folder name. For a duplicate title, the proposed alternative includes the title ID when known. You can edit the name; an existing file or directory must be avoided or the operation cancelled. A nested game root is preserved inside the complete extracted tree and passed to the existing launcher.

Installation records explicit prerequisite, mount, scan, extract, verify, finalise, register and source-removal stages, followed by Completed, Completed — original retained, Failed, Cancelled or Needs attention. **Installations** shows the current file, bytes processed, stage percentage, speed, overall elapsed time and stage ETA. Progress stays below 100% until the terminal result. Cancellation preserves the source; cancelling while a mount command is running waits for that bounded command and mount cleanup. Closing during installation requests cancellation and keeps the window open until cleanup finishes. **Installations → Clear all** hides finished and interrupted history, including after restart. It preserves image files, installed games, mounts and the verification/recovery journals used by My Library. The button is disabled while an installation, reinspection or source cleanup is active.

The helper selects one unused drive letter and mounts the standalone filesystem with `-a -t file -f <image> -m <letter> -o ro,logical,fix`. It requires an accessible exFAT filesystem and a matching read-only `-l -m <letter>` descriptor. Cleanup compares the exact descriptor and Windows device mapping before issuing only normal `-d -m <letter>`. It never formats, mounts writable, force-dismounts, or dismounts all devices. Parent disconnection triggers owned-mount cleanup. Changed or uncertain ownership is reported for manual attention. Only standalone exFAT volume images are supported; partitioned/multipart images, ambiguous game roots, inaccessible entries and reparse points are rejected.

Every source file and empty directory is scanned. Copy uses cancellable Windows file streams with a 1 MiB buffer into `.install-<job-id>\content` under the installation root, with 5% working-space headroom (minimum 64 MiB). Complete source/destination relative file and directory sets must match. Every file length and streaming SHA-256 must match; source/output changes during verification are rejected. One game root must contain `eboot.bin` and `sce_sys` metadata/resources. Installation does not enforce the browser's ELF/SELF compatibility checks. KytyPS5 decides whether it can launch the installed game.

After full verification, the mount is released and staging is atomically renamed on the same local fixed filesystem. An existing destination is never merged or overwritten. The final tree is verified and the library registration is saved and re-read. Library records store title/ID/catalogue, original filename, installed directory/count/size/time, verification, deletion result and launch eligibility. The UI exposes **Installed — Ready for launch attempt** after completion, alongside folder, details, reinspection and the existing launch action. It does not expose Playable status.

Original-image deletion is the last operation. The source is protected against writes/replacement during installation; job ownership is exclusive across browser instances and aliases. Cleanup reacquires the source with exclusive read/delete access, compares its recorded Windows file identity, size and full-image SHA-256, re-verifies the final output, and rechecks persisted registration. Deletion uses that exact file handle, never recursive deletion or a fresh filename search. A mounted/in-use/replaced image, failed copy/hash/finalisation/registration, or cancellation preserves the source. Cleanup failure preserves the installed game and offers an explicit **Retry source cleanup**, which repeats reconciliation. Download records reflect verified installation/removal, and installed library records reference the game directory rather than the deleted image.

Per-job manifests and journals are saved under `%LOCALAPPDATA%\PS5CatalogBrowser\installations`. Restart marks incomplete jobs Needs attention and disables their launch eligibility until reinspection. It never automatically deletes a retained source or detaches an orphaned mount. Inspect any reported mount in OSFMount before starting again; do not detach unrelated volumes. For a registered interrupted installation, reinspect the installed files before explicitly retrying cleanup. Staging cleanup requires the exact job directory, ownership marker and manifest-owned entries; unknown data is retained for attention. Temporary ownership files close/delete with their handles. One browser instance owns each settings directory, preventing stale library writes during registration/deletion.

Startup removes obsolete metadata for unmanaged local entries pointing at the Downloads/Installed containers or their ancestors, and cleared Scan registrations for missing or unsupported nested files. This does not delete files or retire installation/recovery records. Genuine overlapping library paths still block relocation and deletion; the message names the conflicting entry and path.

### Upstream integration and licensing

The official [exFAT Image Builder release](https://github.com/kerrdec97/ps5-exfat-builder/releases/tag/v4.0.2) was inspected at tag `v4.0.2`, commit **`70169323db505895a5aa864d700284a473a8fa13`**. That source snapshot internally declares `APP_VERSION = '3.6.4'`. Its extraction implementation is GUI-bound OSFMount plus Robocopy; no documented, supported headless exFAT extraction interface was found. The released source snapshot contains no licence file or permission grant for reusing its application code. No builder source or binary is included in this application.

This integration independently invokes an existing OSFMount installation and uses Windows streaming copies instead of Robocopy. The [official OSFMount V3 guide](https://www.osforensics.com/tools/OSFMount-Users-Guide.pdf) documents the command interface and includes PassMark's EULA plus ImDisk/LGPL/BSD notices. OSFMount remains separately installed and governed by those terms; no third-party extraction binaries are redistributed. OSFMount 3.3.1000 is the reference release reviewed for this integration. Existing .NET 10 and WebView2 dependencies are unchanged.

The official `https://www.osforensics.com/downloads/osfmount.exe` installer was downloaded for provenance inspection only: version `3.3.1000.0`, valid Authenticode publisher `PassMark Software Pty Ltd`, SHA-256 `5986BEBD3F4954580B5EC910749712E533438A5EF4589C17562F6B07F386CB76`. It was not installed or bundled.

### Validation and limitations

```powershell
dotnet build .\PS5CatalogBrowser.slnx -c Release
dotnet run --project .\PS5CatalogBrowser.Tests -c Release
dotnet run --project .\PS5CatalogBrowser.BrowserTests -c Release
# WPF installation confirmation and restart/ownership checks only:
dotnet run --project .\PS5CatalogBrowser.BrowserTests -c Release -- --installation-ui
# Explicit driver integration; requests temporary UAC approval when prerequisites exist:
dotnet run --project .\PS5CatalogBrowser.Tests -c Release -- --windows-exfat-integration
```

Core tests use generated bytes and an injected mounted filesystem, covering naming, full-tree/hash mismatches, cancellation, interruption, ownership, persistence, finalisation and source preservation. The optional Windows integration generates its own 64 MiB exFAT image with nested directories and synthetic ELF/metadata, then runs the real mount/copy/hash/register/delete path. It skips if OSFMount is absent. The image generator uses the [Microsoft exFAT specification](https://learn.microsoft.com/en-us/windows/win32/fileio/exfat-specification); no commercial game image is required or modified.

Driver/UAC operation and representative game installation still require Windows acceptance with installed OSFMount. Unknown CLI output fails ownership checks safely. Multiple complete read passes are deliberate and can take substantial time. A system/driver crash, power loss or external filesystem interference can require manual reconciliation; journals do not automatically resume deletion. Synthetic extraction or passing a directory to KytyPS5 is not gameplay compatibility evidence.

## Limits

- Active admission uses a snapshot of the selected source, entry, artifact, original catalogue URL and release metadata. Direct queues, native browser transfers (including paused operations) and selected external imports share ownership; retries keep their original identity. A conflicting batch is rejected as a whole. Only unresolved verified completion intents restore an owner after restart; ordinary history and legacy records without identity are not matched speculatively. Separate OptiStore artifact links retain independent admission identities; their managed transfers use the same network queue.
- Managed HTTP and embedded provider downloads share a bandwidth setting, defaulting to **100 MB/s** (decimal megabytes; 0 means unlimited). One managed network transfer uses the shared slot at a time. Provider windows wait before navigation and reserve the slot until their download terminates or the window closes; paused native downloads retain it. Limit edits apply to the next transfer because changing WebView2 throttling in flight can remove its limit. System-browser transfers and local imports are outside this cap. Browser resume depends on the website and remains limited to the original app session. There is no multipart assembly or transfer acceleration.
- Multiple-file PS5 Library entries download all listed files and preserve their paths, but archive part assembly and extraction are not supported. OptiStore entries with multiple links require selecting each desired link individually because the list may mix parts, mirrors and alternative releases.
- Select a listed mirror URL for a single-file download. **Download all files** uses each primary URL; automatic mirror failover is not supported.
- The library uses JSON records rather than a database. Missing paths are marked on restart. Existing downloads are never silently moved or overwritten when the download root changes.
- Compatibility labels are structural only. A catalogue link, `eboot.bin` or process start is never evidence that a game runs.
- Embedded login/popups or provider restrictions may require the external-browser workflow. CAPTCHA, login and waiting steps are manual. HTTP is limited to loopback development; `blob:` and `data:` download URLs are not accepted. No paid-host scraper or authentication bypass is included.
- Browser and external-import staging uses a persisted job root and ownership token with a matching marker in its exact staging directory. Discard checks both partial names and all ancestor directories for links, preserves sibling files, and removes the job directory only when empty. Legacy staging without a matching ownership marker remains visible for manual inspection and is never deleted automatically. Cleanup intent is saved before deletion; missing partials and failed persistence remain recoverable on restart. No staging sweep or automatic resume is performed.

### Local Orbit catalogues and selected downloads (O4a, private use)

In **Settings → Catalogue sources**, choose **Orbit Store — Local encrypted catalogue**, enter a friendly name, and choose separately obtained `.enc` and decoding key files. Keys may be 32-byte binary files, 64 hexadecimal characters (with surrounding whitespace), or the published `catalog_key.h` literal-array format. The header parser accepts one 32-byte array with the inspected include guard; it does not evaluate C expressions. Add/save the source, then use **Test Connection** or **Refresh Now**. Existing HTTP sources remain supported; saved sources without a type are HTTP/JSON.

Source configuration, file paths, enabled state and load diagnostics are saved. A requested download also saves only its selected release transfer metadata in the existing download/library records. Files are read on each load; authenticated JSON stays in memory, with no plaintext disk cache. Missing files and invalid keys/envelopes/schema versions produce source-specific errors. A failed refresh retains the last valid entries for that session; restart requires readable original files. Disabling removes the source's Browse entries; removing deletes only its configuration. Changing source type requires adding a new source.

Orbit games use the existing Browse search and source/platform filters. Each release remains a separate choice with its own ID, provider, version, region, filename, expected size, content/container formats and direct/browser URL roles. Selection follows stable IDs across refresh/reorder. Orbit cover URLs populate Browse thumbnails and details, using the explicit catalogue fallback when the primary fails. Choose an individual release action. Only recognised Archive.org `/download/<item>/<file>` URLs in `url` are direct candidates; the existing HTTP response, size and checksum protections still decide success. Recognised Vikingfile `/f/`, AkiraBox `.com`/`.to` `/file/<id>`, `/<id>/download` or `/<id>/file` and DataNodes file-page routes use the existing browser workflow, preferring `browserUrl` when supplied. Provider labels never establish URL roles. Unknown routes offer **External browser** and **Import completed file** directly in Browse. Browser and import filenames must exactly match the selected expected filename before admission. Download All stays disabled for Orbit; no alternatives or multipart relationships are inferred. Native transfer capabilities and browser session data are never copied into job records. Browser support for live providers remains unverified; provider restrictions may require external import. No Orbit automatic installation or launch is provided.

For live browsing, choose **Orbit Store — Live Catalogue** instead. The official v7 HTTPS endpoint is prefilled; select an available decoding key or leave the key field empty to retrieve the published key automatically when adding the source. No live source is created by default. Enable automatic refresh to fetch on startup and at intervals of at least six hours, or use **Refresh Now** without restarting. Disabled sources do not fetch. **Test Connection** authenticates and validates without publishing Browse entries. Settings and Browse details show the last successful refresh, generation/revision, game/release counts and source-local errors.

The **Available decoding keys** dropdown describes each stored key by supported key ID, originating release (or manual import) and SHA-256 fingerprint. **Download official Orbit key** retrieves the latest stable release's published key; **Import key file** retains manual binary, hex and literal-header support. Imported and downloaded keys are stored under `%LOCALAPPDATA%\PS5CatalogBrowser\keys`, alongside provenance metadata. Existing external key paths remain supported. Downloading an update adds it to the available keys without changing any configured source's selection. Choose a different key and **Save selected** to change an existing source.

Orbit currently publishes the key only inside its source bundle (v1.3.5: about 342 MB). Key retrieval verifies the release API's SHA-256 digest and exact size before reading the bounded key header. Only the official repository release URL and verified GitHub release-asset redirects are allowed, with normal certificate validation and no cookies/default credentials. Temporary bundles are deleted on success, failure or cancellation. A verified stored key for the same release/digest is reused; no source bundle is retained. **Cancel key download** stops retrieval. If upstream metadata/digests or key format are unsupported, automatic retrieval fails and manual import remains available. Opening Settings alone does not fetch keys.

Optionally select an existing local Orbit source as the fallback for this same feed. Its separately loaded entries appear when the live source has no valid session snapshot or is disabled. A valid live snapshot hides that explicitly linked fallback even if the local revision is older. Unlinked sources remain independent; only identical validated release content is automatically hidden as a duplicate. IDs and existing download/library records are never merged or rewritten.

Live retrieval accepts only the official repository's raw HTTPS v6/v7 endpoints, rejects every redirect, uses a separate transport without cookies or default credentials, and enforces a 30-second timeout and an 8 MiB plaintext/40-byte envelope-overhead limit. Complete authentication and schema/identity validation precede publication. Older revisions/generations and changed content under an unchanged generation/revision are rejected. Failed refreshes retain the previous session snapshot. There is no persistent live catalogue cache; restart needs connectivity or the independently supplied local fallback. Normal game-file HTTP transport and provider handling are unchanged.

No keys or catalogue data are bundled; artwork uses only the bounded in-memory thumbnail cache. Provider transfers occur only through individually requested workflows. Embedded browsing starts a tracked transfer only after an actual native file offer is accepted. AkiraBox follows its visible ready link automatically when the page identity and selected filename match; other providers use their displayed instructions. If a provider offers no file, use **External browser** and then **Import completed file**. Direct transfer remains limited to genuine direct-file routes. The private client reuses the independent O1/O2 decoder/parser without copying Orbit GPL implementation code. The current terms review found no express external-client prohibition, but no explicit external catalogue-data licence either. GPL application licensing, public accessibility and private use do not grant rights to metadata, artwork or game files. Use only where applicable permissions and provider terms permit it; no catalogue redistribution or public mirror is provided. See [live feed compatibility and terms](orbit-live-catalogue.md).

Validation: synthetic local-source and selected-release tests run in the Core and WPF Browser suites (`--orbit` runs the source integration checks; `--orbit-downloads` runs controlled HTTP/native/import transfer checks). Transfer checks inspect actual persisted records and bytes, and cover integrity failures, interruption, cancellation, release ownership and finalisation recovery. No commercial content or live provider transfers are test dependencies. Optional private bundled-feed smoke testing uses `--orbit-smoke <catalog.enc> <key-file>` and checks the fixed bundled v6/revision-27 snapshot's 1,601 games and 4,050 release choices; these counts are not assumptions about mutable feeds.
