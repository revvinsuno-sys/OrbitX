# Download completion contract (A4)

`settings.json` remains the sole transaction and library authority. Download admission remains the sole session owner; the existing staging marker proves the exact job reservation. Installation journals and source deletion are unchanged.

Successful game/folder deletion also clears its recorded download entries and entries
under the deleted paths in the final library-removal save. Verification evidence stays
in retained settings records; Downloads removes those rows immediately and after restart.
Failed or partial deletion keeps the rows until completion. This does not expand the
confirmed file deletion paths or delete retained source archives outside those paths.

1. Admission saves the selected artifact snapshot and owned staging reservation before writing bytes. Direct, native browser and external import writers use the existing job staging directory under their reserved download root.
2. Verification enforces transfer/catalogue length, HTML rejection and optional expected SHA-256. Before durable intent, an interruption leaves an interrupted job and retained staging; startup does not infer verification from existence or length.
3. **Pending:** save an intent binding job/selection/source/artifact metadata, staging ownership, final destination, actual length and calculated SHA-256. Failed persistence preserves staging and reports Needs attention; no move occurs.
4. Revalidate ownership and full content, refuse destination collisions and filesystem links, then rename without overwrite. Both paths are under the same root with no reparse ancestors; no cross-volume copy fallback is used. Cancellation is observed before intent persistence; after it, local finalisation runs to a recoverable boundary.
5. **Promoted:** re-hash the final file against the intent, then persist promotion. A crash before this save is recoverable from Pending plus the matching final content.
6. **Completed:** register verified artifact metadata once, then atomically save library and terminal download state together. Failed save rolls back in-memory registration and preserves the previously durable intent. Batch parts share one library registration; only verified parts are included, and an incomplete batch is labelled accordingly.

Startup reconciliation runs under application settings ownership before new admissions. Pending/Promoted transactions revalidate the saved reservation and full SHA-256. Staging-only resumes local promotion; final-only resumes registration. Both paths, neither path, changed content, invalid identity or unsafe paths report Needs attention and preserve all files. Both-path conflicts are conservatively retained even if the final hash matches. Completed transactions are not replayed, including downloads later consumed by the exFAT installer. Legacy downloads without intent are not promoted or given invented verification evidence.

Unresolved intents retain admission ownership until durable completion, block transfer retry, cancellation/discard and history clearing, and protect staging from A3 cleanup. Batch paths remain unavailable to installation until every part completes durably. Repeated native callbacks serialize on the same job; successful repeats return the existing registration. Recovery performs no network request, execution, game deletion or recursive staging cleanup. The ownership marker binds the reservation to its original paths and catalogue selection; it is filesystem ownership evidence, not authentication against a local actor able to rewrite both settings and owned files.

Native download ownership (A5) remains in `BrowserDownloadManager` until WebView2 reports Completed or Interrupted/UserCanceled. Callback failures request cancellation once, suppress further progress notifications, and retain the operation, admission and staging protection while termination is unproven. Explicit cancellation remains available; failures preserve the record and partial bytes. The browser window records ownership before the first native notification and refuses to close while cancellation is pending. Application shutdown also continues observing terminal callbacks; retry closing after termination. Verification blocks closure and cancellation, claims its owner before invoking application callbacks, and runs at most once per transfer. A notification failure after durable Completed reports that failure without re-registering content. Browser persistence errors are propagated to the manager and use fixed diagnostic text so native capability URLs cannot enter recovery errors. The Pending/Promoted/Completed contract and restart reconciliation are unchanged; native transfers do not resume across restart.
